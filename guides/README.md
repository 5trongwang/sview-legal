# 帮助中心内容通道

App 内「帮助中心」的远程清单。与 `whats-new/` 并列：push 到 main 即上线，**不需要发版**。

- 线上地址：`https://sviewapp.com/guides/sview-guides.json`
- 客户端：`GuideCatalogService`（24h 缓存 + stale-while-revalidate）
- 设计与决策：`SView/docs/v1.2.0-guidance-system-design.md` §五 / §七

## 三态兜底：这份文件挂了也不会开天窗

客户端的取数链是 **远程 → 本地缓存 → App 内置 `DefaultGuides.json`**。所以这里推坏了、
推挂了、用户离线，帮助中心都还有内容。代价是：**内置那份不会自动跟着这里更新**，
两边都要改的场合（见下）别只改一处。

## 改内容的规矩

| 你想做什么 | 怎么做 |
|---|---|
| 改错别字 / 补一段说明 | 改对应 article 的文案，**`rev` +1** |
| 加一篇新文章 | 追加一条，`rev` 从 1 起 |
| 下架一篇 | 直接删掉那条 |
| 讲**新版本**才有的功能 | 文章加 `"minAppVersion": "1.3.0"`，老版本自动看不到 |

**`rev` 是红点的锚**，不是文档版本号：客户端比对的是「全部文章 rev 之和」，改任意一篇
或增删任意一篇都会让红点亮起。不改内容就别动 `rev`，否则等于给所有用户发一次假通知。

**`id` 是永久身份**，改文案绝不换 id —— id 一换等于新文章，用户的已读状态、统计分桶全断。
字符集限 `[A-Za-z0-9._-]`。

## 发布次序（唯一一条硬规矩）

**先发 App，再推清单。** 讲新功能的文章如果先上线，老版本用户会读到一篇教他操作
一个不存在的按钮的说明。`minAppVersion` 是这条规矩的兜底，不是替代——填了它也仍然
应该等 App 上架后再推。

## 客户端的防御（推坏了会发生什么）

- `schemaVersion` 高于客户端认识的 → **整份弃用**，回落内置版本
- 单条非法（id 含非法字符 / 重复 id / 未知 `kind` / 无文案）→ **只丢那一条**，其余照常显示
- `anim` 引用了客户端没有的动画 id → 降级成 `images[0]`，没有图就只显示文字

所以最坏情况是「某篇不见了」，不会是「帮助中心整页空白」。改完可以用这个自查：

```bash
python3 -m json.tool guides/sview-guides.json > /dev/null && echo "JSON 合法"
```

## i18n

文案内嵌在 JSON 里（长文进 .strings 是转义地狱且无结构）。**`en` 必填**——它是回落链的
终点；`zh-Hans` 建议填。其余语种缺失会自动回落，不必假装六语齐发。
回落链：精确匹配 → 语言+文字 → 纯语言码 → 中文旧 region 习惯 → `en`。
